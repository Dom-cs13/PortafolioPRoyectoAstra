ASTRA — Referencia del Compilador

Versión: 1.0 (en desarrollo) · Compilador para simulación de biosferas planetarias

1. Introducción y propósito

ASTRA es un lenguaje de dominio específico (DSL) y un compilador optimizador diseñado para modelar, analizar y ejecutar biosferas complejas. Permite definir planetas, atmósferas, cuerpos de agua y formas de vida, así como establecer reglas de evolución, cálculos y reportes. El compilador valida semántica, unidades físicas y reglas ecológicas, transformando descripciones de alto nivel en simulaciones deterministas.

El proyecto incluye un IDE completo (BioSphereIDE) con editor, resaltado de sintaxis, detección de errores en tiempo real, tabla de tokens, consola de salida y visualizador de árbol sintáctico.

2. Sintaxis del lenguaje

2.1 Estructura general

inicio
    simulacion {
        planeta { ... }
        atmosfera { ... }
        agua { ... }
        vida { ... }
        // funciones y otras sentencias
    }
fin

Bloques obligatorios: planeta, atmosfera, agua. vida es opcional.

2.3 Tipos de datos

  • Números: enteros o decimales (ej. 42, 3.1416, 5.97e24, -10)
  • Textos: entre comillas dobles (ej. "Hola mundo")
  • Booleanos: verdadero, falso
  • Listas: secuencias homogéneas, ej. [1, 2, 3], ["a","b"]
  • Nulo: nulo (para variables sin valor asignado)

2.4 Operadores

  • Aritméticos: + - * / ^ (potencia)
  • Comparación: == != < > <= >=
  • Lógicos: y (AND), o (OR)

2.5 Unidades físicas (opcionales)

Se permiten las siguientes unidades después de un número: km, m, g, kg, atm, ppm, Sv, %, °C, h, s, M🜨, R🜨, AU, K, kPa. Ejemplo: temperatura = 25 °C;

El analizador semántico verifica que en sumas y restas las unidades sean compatibles, y que el exponente de una potencia no tenga unidad.

2.6 Sentencias de control

  • Asignación: identificador = expresión;
  • Condicional: si (condición) { ... } sino { ... } (el bloque sino es opcional)
  • Bucle mientras: mientras (condición) { ... }
  • Mostrar (salida en consola): mostrar(expresión); o mostrar expresión;
  • Reporte (estadística): reporte(expresión);
  • Función: funcion nombre(param1, param2) { ... } (las funciones pueden usar retorno = expresión; para devolver valor)
  • Llamada a función: nombre(argumento1, argumento2);

4. Gramática formal (EBNF)

programa         = "inicio", bloqueSimulacion, "fin" ;
bloqueSimulacion = "simulacion", "{", { sentencia }, "}" ;
sentencia        = bloquePlaneta | bloqueAtmosfera | bloqueAgua | bloqueVida
                 | asignacion | mostrar | reporte | if | while | definicionFuncion
                 | expresionSentencia ;
bloquePlaneta    = "planeta", "{", { sentencia }, "}" ;
bloqueAtmosfera  = "atmosfera", "{", { sentencia }, "}" ;
bloqueAgua       = "agua", "{", { sentencia }, "}" ;
bloqueVida       = "vida", "{", { sentencia }, "}" ;
asignacion       = identificador, "=", valor, ";" ;
mostrar          = "mostrar", [ "(", valor, ")" ], ";" ;
reporte          = "reporte", [ "(", valor, ")" ], ";" ;
if               = "si", "(", condicion, ")", "{", { sentencia }, "}", [ "sino", "{", { sentencia }, "}" ] ;
while            = "mientras", "(", condicion, ")", "{", { sentencia }, "}" ;
definicionFuncion= "funcion", identificador, "(", [ listaParametros ], ")", "{", { sentencia }, "}" ;
valor            = expresion | booleano | cadena | lista | nulo ;
expresion        = termino, { ("+" | "-"), termino } ;
termino          = potencia, { ("*" | "/"), potencia } ;
potencia         = factor, [ "^", potencia ] ;
factor           = numero | identificador | "(", expresion, ")" | llamadaFuncion | "-", factor ;
condicion        = valor, [ ("<"|">"|"<="|">="|"=="|"!="), valor ], { ("y"|"o"), condicion } ;
identificador    = letra, { letra | digito | "_" } ;
numero           = digito, { digito }, [ ".", { digito } ], [ "e", [ "+" | "-" ], digito, { digito } ] ;
cadena           = '"', { carácter - '"' }, '"' ;
lista            = "[", [ valor, { ",", valor } ], "]" ;
nulo             = "nulo" ;
booleano         = "verdadero" | "falso" ;

5. Fases del compilador (detalle técnico)

5.1 Analizador léxico (Lexer)

El lexer convierte el código fuente en una secuencia de tokens utilizando expresiones regulares. Reconoce palabras reservadas (case-sensitive, minúsculas), identificadores, números (enteros, decimales, notación científica), cadenas, operadores y símbolos. Además, detecta errores léxicos:

  • Identificador inválido: comienza con número, ej. 123abc
  • Carácter ilegal: cualquier carácter no definido (ej. @, $, #, &, ?, |, \\, ~, `)
  • Cadena sin cerrar: falta la comilla de cierre al final de la línea

Los errores léxicos se muestran en la consola y se subrayan en el editor con una línea ondulada roja.

5.2 Analizador sintáctico (Parser)

El parser construye un Árbol de Sintaxis Abstracta (AST) siguiendo la gramática LL(1). Valida la estructura global (presencia de inicio y fin), el balance de llaves, el uso correcto de punto y coma, y las reglas de precedencia de operadores. Si encuentra un error, reporta la ubicación exacta y el token esperado.

Ejemplos de errores sintácticos:

  • Falta de ; al final de una sentencia
  • Falta de { después de planeta
  • Uso incorrecto de si sin paréntesis alrededor de la condición
  • Expresiones mal formadas, ej. (5 + sin cerrar

5.3 Analizador semántico

Esta fase recorre el AST y aplica reglas semánticas para garantizar la coherencia del programa. Incluye:

  • Tabla de símbolos: gestiona ámbitos anidados (global, simulacion, if, while, función). Cada símbolo almacena: nombre, tipo (numero, texto, booleano, lista, nulo, funcion), valor, unidad (opcional), línea de declaración y ámbito.
  • Verificación de variables no declaradas: no se puede usar un identificador sin antes asignarle un valor (error SEM-001).
  • Compatibilidad de tipos: se comprueba que las operaciones respeten los tipos (no sumar texto con número).
  • Unidades físicas: en suma/resta las unidades deben coincidir; el exponente de una potencia no puede tener unidad.
  • Variables obligatorias: dentro de planeta deben declararse masa y radio; en atmosfera, presion y co2; en agua, estado_liquido. Si falta alguna, se reporta error SEM-040 o SEM-041.
  • Coherencia en condiciones: los operadores relacionales (<, >, etc.) solo se permiten entre números. Los operadores lógicos y/o requieren operandos booleanos.
  • Funciones: se comprueba que la función esté definida antes de ser llamada y que el número de argumentos coincida con los parámetros declarados.

Códigos de error semántico comunes:

  • SEM-001: Variable no inicializada
  • SEM-002: Función no definida
  • SEM-010: Operador requiere tipos numéricos
  • SEM-011: Operador relacional requiere tipos numéricos
  • SEM-014: Incompatibilidad de tipos en asignación
  • SEM-020: Condición debe resultar booleana
  • SEM-030: Unidades incompatibles en suma/resta
  • SEM-031: Exponente con unidad física inválida
  • SEM-040: Bloque obligatorio faltante
  • SEM-041: Variable requerida faltante en bloque

5.4 Tabla de símbolos (estructura)

La tabla de símbolos se implementa con una pila de ámbitos. Cada ámbito es un diccionario nombre → símbolo. Las operaciones principales:

  • PushScope(name) – entra a un nuevo ámbito
  • PopScope() – sale del ámbito actual
  • LookUp(name) – busca el símbolo en el ámbito actual y ancestros
  • AddSymbol(sym) – añade un símbolo en el ámbito actual
  • UpdateSymbol(name, newSym, level) – actualiza un símbolo en un nivel específico

La información almacenada permite la verificación semántica y es utilizada durante la ejecución para obtener valores de variables.

5.5 Ejecución / simulación

Una vez superadas todas las fases, el compilador interpreta el AST. El motor de simulación recorre el árbol ejecutando las sentencias en orden: asignaciones, condicionales, bucles, funciones, mostrar y reporte. Soporta operaciones aritméticas, lógicas y de comparación, así como manipulación básica de listas.

6. Ejemplos completos

Ejemplo 1: Simulación básica con condicional

inicio
    simulacion {
        planeta { masa = 1000 kg; radio = 100 km; }
        atmosfera { presion = 0.5 atm; co2 = 800 ppm; }
        agua { estado_liquido = falso; }
        vida {
            temperatura = 30;
            si (temperatura > 25) {
                mostrar("Alerta: temperatura alta");
            }
            reporte("Condiciones extremas");
        }
    }
fin

Ejemplo 2: Función y bucle

inicio
    simulacion {
        planeta { masa = 1.0 kg; radio = 1.0 km; }
        atmosfera { presion = 1.0 atm; co2 = 300 ppm; }
        agua { estado_liquido = verdadero; }
        vida {
            funcion cuadrado(x) {
                retorno = x * x;
            }
            contador = 0;
            mientras (contador < 5) {
                mostrar(cuadrado(contador));
                contador = contador + 1;
            }
        }
    }
fin

Ejemplo 3: Listas y unidades

inicio
    simulacion {
        planeta { masa = 5.97e24 kg; radio = 6371 km; }
        atmosfera { presion = 1.0 atm; co2 = 400 ppm; }
        agua { estado_liquido = verdadero; }
        vida {
            temperaturas = [15, 20, 25] °C;
            promedio = (temperaturas[0] + temperaturas[1] + temperaturas[2]) / 3;
            mostrar("Promedio: ", promedio, "°C");
        }
    }
fin

ASTRA no es una biblioteca sobre un lenguaje existente: es un DSL completo con su propio analizador léxico, parser, árbol de sintaxis abstracta (AST), verificador semántico y motor de simulación. Cada construcción sintáctica se asigna directamente a primitivas de simulación física: gradientes atmosféricos, flujo estelar, ciclos biogeoquímicos y dinámicas de población.

El pipeline de compilación transforma consultas de habitabilidad de alto nivel en simulaciones numéricas paralelizadas, reduciendo semanas de cómputo en supercomputadoras a segundos de ejecución determinista.
